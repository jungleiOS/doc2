# DeepSeek 的 Super-agent 能 7×24 干活了，程序员的不可替代性还剩什么？

先说个我自己的判断：**没人合的 PR，跟没干是一样的。**<!-- 判断句 -->7×24 干活的是它，盯着的还得是人。

先说说这个原型本身。DeepSeek Harness 团队 10 月 31 号发了一篇[《Super-agent 设计探索》](https://www.ithome.com/1/020/615.htm)，原型也开源了（GitHub 上叫 dsh-superagent-prototype），官方自己交代得很清楚，这是验证技术路线的，不是正式产品。

![IT之家 2026-10-31 报道：DeepSeek Harness 官方团队发布《Super-agent 设计探索：迈向更自主的 Agent 系统》](https://iili.io/ns2tC0b.png)

（图源：[IT之家](https://www.ithome.com/1/020/615.htm)，2026-10-31）

我把原文读了一遍。说真的，7×24 反而不是重点。重点是里面有个特别朴素的观察：**一个人，通常只能同时跟进 3 到 5 个活跃会话。**<!-- 判断句 -->整套架构，什么 Router 分活、Worker 干活、Watchdog 盯着，全是围着这个限制转的。最会做 agent 的团队也认，瓶颈已经不在模型了，在人盯不过来。

![DeepSeek《Super-agent 设计探索》官方整体系统架构图：外部事件经两级过滤进入 Router 层，分派至多个相互隔离的 Worker，Watchdog 做外部监控](https://iili.io/ns2ZPJR.jpg)

（图源：DeepSeek Harness《Super-agent 设计探索》官方文章配图，[IT之家转引](https://www.ithome.com/1/020/615.htm)，2026-10-31）

题主的问题描述里有一句，说生产力瓶颈是人的注意力。我很同意。但顺着往下想，注意力成了瓶颈，不代表注意力就省下来了。恰恰相反，是注意力的价钱变了。<!-- 判断句 -->

哪部分在贬值？

把需求翻译成代码这件事，定价大概率是崩了。「想到」和「做到」之间的沟，被 AI 填平了大半。以前程序员有口饭吃，靠的就是站在这条沟里帮人搭桥，把老板和客户的大白话变成能跑的东西。这段搭桥活现在接近零边际成本，谁都能直接指挥 agent 干，靠它攒年限的老路，大概率走不通了。<!-- 判断句 -->这个话题我上个月专门写过一篇（[《AI 编程普及到底是替代程序员，还是把创造力平权给普通人？》](https://www.zhihu.com/question/2091803976455013001)），感兴趣可以去看，这里只取结论。还有「人在场」这回事，以前值班值钱，有一部分就是图你出事的时候在电脑前。agent 常驻之后，这条越来越不值钱。

最让我自己有感觉的是手速。Anthropic 十月中旬发过一份就业报告，工程师人均提交量涨到半年前的 5.1 倍。听着吓人吧。但差不多同期有个研究，跟踪了 50 万个 GitHub 开发者，用 agent 的人提交数涨了 240%，真正发出去的版本只涨了 30%。<!-- 判断句 -->多出来的那一大坨是什么，你猜。所以现在谁再拿提交数跟我说他产出高，我脑子里会自动打三折。

哪部分在涨价？

我自己的感觉是三个。

一个是**写边界**。我们自己的做法很土：改动尽量切小，一次让 agent 做一件事，边界条件在需求里就显式列出来，空值怎么办、超上限怎么办、并发怎么办。列不出来的点，先别写代码，回去问。你再看 DeepSeek 那个两级过滤，先拿程序规则筛掉明显无关的，再交给模型判断要不要动手。说白了是一件事：都是在动手之前，把「什么情况该怎么办」先定死，别让它到时候自己猜。他们把这个原则做进了系统，咱们把它写进了需求，同一个意思。<!-- 判断句 -->

一个是**验收**。有组数据我一直记着：同一个人，同一个代码目录，AI 写的代码跟手写代码，90 天内的回滚率没有可检测差异。平均水平是真对齐了，拿 AI 代码水平说事的阶段过去了。但报告自己也提醒了一句，AI 的错误可能更难被发现。语法全对，跑得也挺好，就是埋在你想不到的地方。<!-- 判断句 -->所以「能看出坑」这件事，从加分项变成了定价依据。以前按你写了多少行算钱，往后按你能拦住多少坑算钱。拦的什么坑？报告自己提醒过的那种：AI 的错语法上完全成立，跑起来大部分时候也对，唯独埋的位置刁钻，不撞上不算数。<!-- 判断句 -->

再一个是**兜底**。报告里说回滚率无差异，说的是 90 天内的平均水平；报告自己提醒的那句才是重点，AI 的错更难被发现，发现的成本集中在那撮埋得刁钻的错上。<!-- 判断句 -->测试只管代码跑不跑得动，管不了的事还有一堆：数据写进去没有，写得对不对，别的模块有没有被连带改坏。<!-- 判断句 -->这些没人问的问题，恰恰是人还不可替代的地方。agent 越自治，没人问的角落越多。<!-- 判断句 -->

![自制示意图：agent 接管之后，正在贬值的动作（翻译代码/在场/手速）与正在升值的动作（写清边界/快速验收/兜底深度）](https://iili.io/ns2tQYx.png)

（图源：自制，依据 DeepSeek《Super-agent 设计探索》与 Anthropic 2026-10-16 就业报告）

还有个细节，不知道你注意到没有。Super-agent 的设计里，干活的 Worker 是不直接跟人说话的，统一由 Router 对外汇报，而且只有确认找到简单修复方式之后才来烦你。

乍听挺贴心。细想一下其实挺吓人的：**它替你决定，什么叫值得打扰你的事。**<!-- 判断句 -->以前 agent 是你说一句它动一下，错也错在你眼皮底下。现在它自己挑活干，错了就错在你看不见的地方，还顺带给你打包好了结论。

![智东西/新浪财经 2026-11-01 报道：DeepSeek 公布 Super-agent 底层架构并开源原型（GitHub 仓库 dsh-superagent-prototype）](https://iili.io/ns2tGmN.png)

（图源：[智东西，新浪财经专栏转载](https://finance.sina.com.cn/tech/csj/2026-11-01/doc-inixepty4335109.shtml)，2026-11-01）

所以「还剩什么」，我的答案可能不太好听。

贬值的那些，翻译、在场、手速，确实是回不去了。涨价的那部分，写边界、验收、兜底，听着像安慰，其实门槛比原来高。原来你只管写代码，现在你得对结果负责，而结果出事的时候，找到的第一个还是你，不是 agent。<!-- 判断句 -->

说到底，不可替代性是会变的。以前会写代码就能吃十年，往后再值钱的本事，可能也就管用一两年。想靠一个身份吃一辈子，越来越不现实了。

最后留三个问题，不用信我，拿它们量自己就行。

最近一个月，你有没有提前预判过 agent 会怎么搞砸，并且真的拦下来一次？我自己能做到的版本是这样的：排期宽裕的时候逐文件看变更，不求看出问题，只为看懂这次改动干了什么，上线后出事能快速定位。<!-- 判断句 -->

你最得意的那段产出，agent 自己就能验收吗？能的话，这活儿它从干到查全包了，你就插不上手了。<!-- 判断句 -->到时候值钱的不是干活的人，是决定什么叫干完的人。<!-- 判断句 -->

还有，假如明天给你一个常驻 agent，你敢让它没人盯着的时候动生产环境吗？不敢的那部分，就是你目前还值钱的部分。但说实话，这是个存量，正在被一点一点啃，别当铁饭碗供着。<!-- 判断句 -->
