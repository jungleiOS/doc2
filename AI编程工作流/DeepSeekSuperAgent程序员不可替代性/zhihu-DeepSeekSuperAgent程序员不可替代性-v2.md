# DeepSeek 的 Super-agent 能 7×24 干活了，程序员的不可替代性还剩什么？

先说一件真事：我看到 Super-agent 原型的第一反应，是先去翻它发的修复请求（Pull Request，就是程序员提交改动、等人工合并的那张「申请表」）有没有人合。

7×24、没人 @ 也主动认领、复现 Bug 修好才出声——这套描述每个字都在暗示「以后的仓库不需要人了」。可我过去一年基本靠 agent 写代码，经验就一条：**agent 越猛，我花在「看它干活」上的时间越多，不是越少。**<!-- 判断句 -->

题主说生产力瓶颈是人的注意力，这话我认。顺着往下想：人的注意力成了瓶颈，注意力本身就会开始被算账——哪部分注意力还值钱，哪部分正在变白菜价。<!-- 判断句 -->

7×24 干活的是它，7×24 兜底的目前还是我。先给结论：程序员的不可替代性，剩下的部分是对结果负责的注意力。下面按题主点名的来：我是重度使用者，讲我这半年的真实变化，再给判据清单。

## 先把 7×24 放一边，原文里有个更关键的数字

DeepSeek Harness 团队 10 月 31 日发的[《Super-agent 设计探索》](https://www.ithome.com/1/020/615.htm)，我通读了一遍。原型已开源（GitHub 上的 dsh-superagent-prototype），官方明确说「用于验证技术路线，并非正式产品」。<!-- 判断句 -->

## 注意力账本：你的动作会记进两本账

「程序员的不可替代性」是个太粗的问法。我这半年的体会是：先别急着下结论，把日常动作分分类——一本账记正在贬值的，一本账记正在升值的。

**正在贬值的：**

一是「把需求翻译成代码」。这个我上个月刚用一整篇展开过（[《AI 编程普及到底是替代程序员，还是把创造力平权给普通人？》](https://www.zhihu.com/question/2091803976455013001)），结论不变：翻译这层的定价大概率已经崩了。<!-- 判断句 -->

二是「在场」。以前团队里值钱的有一部分是「出事了有人在线」，agent 常驻之后，这条的贡献在快速缩水。<!-- 判断句 -->

三是「手速」。Anthropic 10 月 16 日的报告里，工程师人均代码提交量是半年前的 5.1 倍。但同一时期，有研究（覆盖 50 万 GitHub 开发者）显示用 agent 的人 commit 涨 240%、真正发出去的 release 只涨 30%——多出来的提交大量是半成品和来回折腾。<!-- 判断句 -->拿 commit 数给自己计价，等于拿一笔正在通胀的货币记账。<!-- 判断句 -->

**正在升值的：**

一是**写清边界的能力**。给 agent 下指令时，把空值、上限、并发这些边界条件显式写出来——写不出来的地方，多半说明需求本身还埋着坑。Super-agent 原文里的两级过滤（先程序规则、再模型判断）干的就是这件事，只是它把边界检查自动化了；人对 agent 的价值，同样压在这一步。<!-- 判断句 -->

二是**快速验收的判断力**。Anthropic 那份报告里，同一个人、同一个代码目录，AI 写的代码和手写代码在 90 天内的被回滚（revert，改错了被撤销）率没有可检测差异——平均水平已经对齐。<!-- 判断句 -->真正的分水岭在长尾：剩下那一小撮错语法全对、跑起来大部分时候也对，埋的位置很刁钻。这份报告自己也提醒，AI 的错误可能比人的更难被发现。<!-- 判断句 -->所以「会不会验收」从加分项变成了定价依据：计价方式正从「按你写了多少行」换成「按你能看出多少坑」。<!-- 判断句 -->

三是**兜底的领域深度**。这是我的实测：上个月我们让 agent 跑一个批处理，往数据库里批量写对账单。它全程报 success、退出码 0——结果写库的操作一条都没成，它把「命令执行了」当成了「事情办成了」。<!-- 判断句 -->最后是一条 SELECT 语句对账时发现行数不对才捞回来的。这种「沉默的失败」不在任何测试覆盖里：测试问的是「代码跑没跑」，它答对了；没人问「数据进没进库」。<!-- 判断句 -->从那以后我们团队多了一条死规矩：凡是 agent 干的写操作，验收必须有一条独立的对账查询。agent 越自治，这类失败越容易在你看不见的地方发生，兜底也越值钱。<!-- 判断句 -->

## agent 越自治，人的注意力越贵

听起来 Super-agent 的设计是在替人省注意力，我的体感正相反：它省的是「操作」，贵的是「判断」。<!-- 判断句 -->

这套设计里有个细节我很在意：干活的 Worker 不向用户汇报，统一由 Router 对外说话，而且按原文的投机执行策略，只有确认问题并找到简单修复方式后才交付结果。换成大白话：**它主动替你决定什么是值得打扰你的事。**<!-- 判断句 -->

以前 agent 是你说一句它动一下，错也错在你看得见的地方；现在它自己会挑活干，错就容易错在你看不见的地方。<!-- 判断句 -->

## 收尾：一个能带走的自检清单

不用信我任何一句，拿这三个问题量自己：

一，你最近一个月有没有过一次**预判了 agent 会怎么搞砸、并提前拦住**的经历？我自己的版本：现在凡是让 agent 碰生产数据，我先让它把「打算怎么验证写成功了」写出来，写不出来的活直接退回去。拦下过，你在升值账上；一次都没有，值得想想自己是不是在贬值账上。<!-- 判断句 -->

二，把你最得意的一段产出拿出来，**它能不能被 agent 自己验收？**能自我验收的产出，定价权大概率会滑向「定验收标准的人」那边。<!-- 判断句 -->

三，如果明天给你一个常驻 agent，你敢让它**无人监督地动生产环境**吗？不敢的那部分，是你目前还不可替代的部分——但这是个会被慢慢啃掉的存量，别当铁饭碗供着。<!-- 判断句 -->

不可替代性不是一种身份，是一笔持续结算的账。Super-agent 上线之后，这笔账只会越算越勤。
