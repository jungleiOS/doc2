# 内容自荐筛选机制

> 知乎创作中心「内容自荐」（`https://www.zhihu.com/creator/recommend`）的自荐配额分配方法。
> 目标：每月把有限的自荐次数，花在期望收益最高的自有内容（回答 / 文章 / 视频）上。
> 最后实测日期：2026-08-24（ego-browser 通道）。

---

## 1. 平台规则与页面事实（设计前提）

以下均为实测，不是推测：

| 事实 | 来源 |
|---|---|
| Lv4–Lv7 每月默认 3 次；Lv8–Lv10 每月默认 **5 次**，次月 1 日清零（不用即作废） | 自荐规则弹窗 |
| 自荐优质内容、内容被编辑推荐，有机会获奖励次数；每篇内容最多 1 个奖励次数，**奖励次数 30 天有效** | 自荐规则弹窗 |
| 门槛：回答 ≥300 字，视频 ≥1 分钟 | 页面提示文案 |
| 2025-12-24 起自荐以「超赞包」执行加量 | 自荐规则弹窗 |
| 同一篇内容可多次自荐（记录中「买平板HUAWEI还是ipad?」出现两次） | 自荐记录 |
| 自荐页面三个 tab：回答 / 文章 / 视频，只展示**标题 + 发布时间 + 自荐按钮**，无互动数据 | 页面实测 |
| 自荐记录（`/creator/recommend/record`）每条有「加量成功 / 查看数据」，可回采加量效果 | 页面实测 |
| 本账号上次自荐是 2021/01，此后次数一直清零浪费 | 自荐记录 |
| 本账号视频 tab 仅 5 条，全是 2020–2021 老视频 | 视频 tab |

**核心推论**：自荐页面本身不提供任何筛选依据（无赞/阅数据），所以机制必须是三段式——**页面粗筛 → 内容页补数据 → 配额分配**。

---

## 2. 第一性原理

自荐是**放大器，不是复活甲**。

> 期望收益 = 加量带来的增量曝光 × 单次曝光的价值

- 增量曝光取决于内容是否已被算法验证：冷启动数据好 → 加量效率高；死贴加不动量。
- 单次曝光价值取决于内容的长尾性（曝光是否复利）与引流/变现能力（流量来了留下什么）。

---

## 3. 四层漏斗

### 第 0 层 · 资格门槛（不过即跳过）

- 回答 ≥300 字；视频 ≥1 分钟
- 本月已自荐过的跳过（除非明确追加）

### 第 1 层 · 硬否决（任一命中即淘汰，不打分）

- **时效已过**：过季促销（「2021 双十一」「2026 返校季」过季后）、已下架产品
- **自己不再站台**：观点过时、参数有误的旧内容
- **被限流过**：判过 AI 创作 / 违规的内容，加量等于二次提交证据
- 视频 tab 现状：全是 5 年前老视频，整体否决，视频位每月不用纠结

### 第 2 层 · 打分（E × L × V，乘法，满分 125）

任一因子接近零即出局，乘法天然体现短板效应。

**E 算法验证分**（已有热度 = 加量效率高；打开内容页抓赞同/收藏/评论）：

| 分 | 条件 |
|---|---|
| 5 | 赞 ≥500 或收藏 ≥1000（已被算法反复验证） |
| 4 | 赞 100–500，互动率正常 |
| 3 | 赞 20–100，冷启动有信号 |
| 2 | 赞 <20，信号弱 |
| 1 | 0 赞 0 评死贴（加不动） |

**L 长尾价值分**（曝光是否复利）：

| 分 | 条件 |
|---|---|
| 5 | 常青搜索型：「怎么选」「为什么」类科普/选购指南，明年今天仍有人搜 |
| 3 | 半时效：型号本代仍在售、话题仍在周期内 |
| 1 | 纯热点 / 纯促销，一周寿命 |

**V 单次曝光价值分**（流量来了能留下什么）：

| 分 | 条件 |
|---|---|
| 5 | 文末引流主文/系列文，或挂好物推荐链接，曝光直接转化 |
| 3 | 领域内涨粉型内容，无直接转化 |
| 1 | 孤立内容，看完即走 |

### 第 3 层 · 配额策略（每月 5 次怎么花）

- **3 次投新**：当月新发且冷启动数据最好的 3 篇，发布 48–72 小时后投（先给算法验证窗口，再放大）
- **2 次投长青**：历史内容里 E、L 双高的
- **月末清零前必须花完**：剩余次数按第 2 层总分从高到低用掉
- 奖励次数 30 天有效，**优先消耗临期的**

## 4. 复盘闭环

每次自荐 7 天后，去「自荐记录 → 查看数据」回采加量前后曝光增量，在 `outlines/选题历史.md` 追加「自荐复盘」行。

发现系统性偏差（如 E 分高但加量不动）→ 说明超赞包放大逻辑变了 → 调整分档阈值。闭环即：**测量 → 假设 → 验证 → 迭代**。

---

## 5. 落地流程（每月一次，约 10 分钟）

1. 抓候选：ego-browser 打开 `creator/recommend` 三个 tab，提取标题 + 时间 + 链接
2. 第 0、1 层纯按标题和时间过滤，把 38 页候选压到个位数
3. 逐个打开候选内容页，抓赞/收藏/评论，打 E 分
4. L 看标题类型对档；V 看文末是否有引流/好物链接（对照本仓库文章文件）
5. 出推荐单 → 用户确认 → **自荐按钮永远用户自己点**，Agent 只整理候选

### 5.1 抓取脚本（2026-08-24 实测可用）

打开页面（ego-browser 通道，task space id 8）：

```js
const ts = await claimTaskSpace(8);
const tab = await openOrReuseTab('https://www.zhihu.com/creator/recommend', {wait:true});
await new Promise(r=>setTimeout(r,4000));
```

切换 tab（回答 / 文章 / 视频）：

```js
(()=>{const els=[...document.querySelectorAll("*")].filter(e=>e.children.length===0&&(e.innerText||"").trim()==="文章");if(els.length){els[0].click();return "ok"}return "nf"})()
```

提取内容链接（去重后）：

```js
(()=>{const rows=[...document.querySelectorAll("a")].filter(a=>a.href&&(a.href.includes("/p/")||a.href.includes("/answer/")||a.href.includes("/zvideo/"))).map(a=>({t:(a.innerText||"").trim().replace(/\s+/g," ").slice(0,60),h:a.href})).filter(x=>x.t.length>3);const seen=new Set();const out=[];for(const x of rows){if(!seen.has(x.h)){seen.add(x.h);out.push(x)}}return JSON.stringify(out)})()
```

注意：回答 tab 有分页（38 页），只排近期的就够——第 1 层会按时间否决掉大部分旧内容；要挖长青老内容时翻页或直接走「内容管理」页。

### 5.2 打开「自荐规则」弹窗

```js
(()=>{const els=[...document.querySelectorAll("*")].filter(e=>e.children.length===0&&(e.innerText||"").trim()==="自荐规则");if(els.length){els[0].click();return "clicked"}return "notfound"})()
```

读弹窗后记得关（点「知道了」），否则弹窗文本会污染后续 tab 的 innerText 抓取。

---

## 6. 禁忌

- Agent 不替用户点「我要自荐」，只整理候选和打分
- 打分必须有抓到的数据支撑，抓不到就如实标注并降级，禁止拍分
- E 分数据必须现场抓，不凭记忆里的旧数据
- 每月执行后把入选/弃选结果留痕（`outlines/选题历史.md`），避免下月重复评估
