# 点赞用户分诊流水线 · 运行说明

每天从知乎「赞同/喜欢了我的内容」通知里捞出「常给我点赞的人」回赞（R 级，按互动亲密度），并给出回关建议（A/B 级）。回关动作由用户本人在知乎手动完成；回赞交给 engage 脚本代执行。

## 文件

- `scripts/liker-scan/fetch-likers.mjs` — 抓取脚本（驱动 ego-browser，顺带对带「感谢」按钮的点赞通知点感谢，并累计互动亲密度）
- `scripts/liker-scan/score-likers.mjs` — 评分分级脚本（纯本地，不需要浏览器）：A/B/C/D 回关建议 + R 级回赞名单
- `scripts/liker-scan/engage-likers.mjs` — 互动执行脚本：对 report 里 R 级用户模拟真人阅读后回赞（真实对外操作）
- `scripts/liker-scan/backfill-seen.mjs` — 一次性回填：从全部 raw-*.json / engage-*.json 累计 likeCount/likeDays/lastEngaged，日常不需要跑
- `raw-YYYY-MM-DD.json` — 每日原始抓取（去重后的用户列表 + 资料）
- `report-YYYY-MM-DD.md` — 每日分级报告（A/B/C/D 表 + 「常点赞用户（R 级）」区块）
- `engage-YYYY-MM-DD.json` — 互动执行明细（每人赞了哪些内容、成功/跳过及原因）
- `seen-users.json` — 已见集合：token → { firstSeen, lastSeen, lastGrade, likeCount, likeDays, lastEngaged }

## 手动运行

```bash
# 1. 抓取最近 2 天（默认），输出 raw-今天.json
node scripts/liker-scan/fetch-likers.mjs
# 窗口可调：node scripts/liker-scan/fetch-likers.mjs 3

# 2. 评分出报告（含 R 级回赞名单）
node scripts/liker-scan/score-likers.mjs
# 指定日期：node scripts/liker-scan/score-likers.mjs 2026-10-21

# 3. 对 R 级名单回赞（真实点赞，慎跑）
node scripts/liker-scan/engage-likers.mjs

# 仅首次迁移时需要：从已有 raw/engage 文件回填 seen-users.json
node scripts/liker-scan/backfill-seen.mjs
```

前提：ego-browser 已登录知乎（浏览器 profile 有知乎登录态）。脚本会自动创建/复用 taskSpace（抓取用 `liker-scan`，互动每次运行建独立 space `liker-scan-engage-<runId>`），跑完自动 `finish({keep:[]})`。

## 分级规则（阈值在 score-likers.mjs 顶部 THRESHOLDS / R_LEVEL，可调）

**A/B/C/D 表 = 回关建议**（只列本轮新抓的用户，老用户不重复出现）：

- **A（回关+回赞）**：创作者（回答≥5 或 获赞≥1000）且方向重合（简介/昵称含数码、手机、平板、充电、AI、科技、评测等关键词）
- **B（可回关）**：获赞≥1万 或 粉丝≥5000 的大号
- **C（只回赞）**：普通活跃号
- **D（跳过）**：零回答且粉丝<50 的小号

**R 级 = 回赞名单**（报告文末区块，按互动亲密度，与 A/B/C/D 独立）：

- 入列条件：累计点赞 likeCount ≥ 2，或 点赞天数 likeDays ≥ 2（跨天点赞）。只赞过 1 次的新用户不进 R 级。
- 亲密度档：**铁粉**（likeCount≥3 或 likeDays≥3，回赞 2 篇）/ **常客**（其余，回赞 1 篇）。
- 本轮动作：① 当天新入列的人标记「新入列（观察一天）」，不急着回赞；② 其余按档位「回赞N篇」。无冷却期，同一用户只要常点赞每轮都会回赞。
- likeCount/likeDays 由 fetch 每日累计进 seen-users.json；`backfill-seen.mjs` 用历史 raw 文件回填过一次。注意回填的 likeDays 是近似值（raw 里点赞事件只记时刻不记日期，窗口内多次点赞归入首次出现日），逐日跑 fetch 后新数据无此偏差。

抓不到资料的用户（风控/接口失败）分级为 C，报告里粉丝/获赞显示「—」，不当成 0。

## engage 互动执行（真实对外操作）

- 名单来源：report 的「常点赞用户（R 级）」区块里本轮动作是「回赞N篇」的人（不再看 A/B 级）。15 人上限只作用于要回赞的人；新入列的也写进输出但不占名额。
- 每人回赞篇数按档位：铁粉 2 篇、常客 1 篇；无冷却期。
- 回赞成功的用户自动回写 seen-users.json 的 lastEngaged = 当天。
- 节奏：用户之间随机 60-180 秒；每篇页面停留 20-40 秒、分 2-4 次滚动后再点赞。
- 安全约束：只点 DOM 里第一个 `.VoteButton`（目标内容自己的按钮，页面推荐流里也有同类按钮，不能误点）；点之前确认按钮文案为「赞同」（非「已赞同」、无 `is-active`），点之后校验变为已赞状态，对不上就跳过并记录，不硬点。
- 输出 `engage-YYYY-MM-DD.json`：每人 token、档位、目标篇数、实际赞了几个、内容链接、失败/跳过原因。

## 常见失败与处理

1. **抓到 0 人 / 通知列表为空**：多为 ego-browser 的知乎登录态失效。先在浏览器里手动打开 zhihu.com 确认已登录，再重跑。
2. **滚动加载提前停止（漏抓）**：脚本按「连续 3 轮条目数不变」判定到底；若知乎改懒加载策略导致误判，把 fetch-likers.mjs 里 `stableRounds >= 3` 调大。
3. **用户资料抓取失败（fetchFailed > 0）**：`/api/v4/members/{token}` 被限流。脚本对每个用户已有 700-1200ms 随机延时；失败的用户重跑时会自动重试（只有 seen-users.json 里没有的 token 才会发请求）。
4. **聚合通知「等N人」**：脚本会自动点开展开；若展开按钮文案变化（不再是 `等N人`），聚合条目会只抓到前 3 个人名，需要在 fetch-likers.mjs 的 collectItems 里同步改匹配正则。
5. **「AI」关键词误伤**：英文关键词按单词边界匹配（"attain" 不会命中 "AI"），新增英文关键词时保持纯字母写法即可自动走词边界。
6. **感谢按钮点了 0 个**：截至 2026-10-21，桌面网页版通知中心（含顶部铃铛浮层）没有「感谢」按钮，条目里只有人名链接和内容链接。fetch-likers.mjs 里保留了感谢逻辑：一旦知乎上线该按钮（文案恰为「感谢」）会自动点击并按人去重；长期为 0 属正常。
7. **engage 报「未找到赞同按钮」**：先人工打开对应链接确认按钮存在。若按钮明明存在，多是知乎按钮文案带零宽字符（\u200b）导致前缀匹配失败——脚本已统一剥掉零宽字符，仍报错则检查 engage-likers.mjs 的 voteButtonState。
8. **engage 报「已赞过」**：该内容之前赞过，属正常跳过。
9. **中途停止 engage 必须杀干净**：手动 `pkill -f engage-likers` 只会杀外层 node，浏览器端 `ego-browser nodejs -e` 子进程会残留并继续写结果文件（还会 finish 掉共享 taskSpace 把新跑搞崩）。正确姿势：`pkill -f engage-likers; pkill -f 'liker-scan-engage'`。脚本现为每次运行建独立 taskSpace（`liker-scan-engage-<runId>`），避免新旧运行互相踩踏。

## 定时任务建议

抓取依赖本机登录态且要控制节奏，建议本地 cron 而非云端：

```cron
# 每天 09:23 抓前两天窗口，09:30 出报告（错峰整点）；engage 涉及真实点赞，不建议无人值守定时跑
23 9 * * *  cd /Users/jiangjun/Documents/kimi/Workspaces/zhihu && /usr/bin/env node scripts/liker-scan/fetch-likers.mjs 2 >> /tmp/liker-scan.log 2>&1
30 9 * * *  cd /Users/jiangjun/Documents/kimi/Workspaces/zhihu && /usr/bin/env node scripts/liker-scan/score-likers.mjs >> /tmp/liker-scan.log 2>&1
```

注意：窗口是「最近 N 天」，重复用户不会重复消耗 API 请求（seen 集合跳过），天天跑不会增加风控压力；报告里的 A/B 级只含新面孔。
