# 知乎选题助手（zhihu-question-scout）

从用户的知乎**关注的问题 + 邀请回答 + 创作中心推荐问题**中（来源优先级：**关注的问题 > 邀请 > 推荐**——关注的问题是自己主动标记过感兴趣的，意图纯度最高），基于「曝光份额 × 机会 × 供给 × 问题类型」四因子模型（见第 5 步），每次选出 **7 个** 期望收益最高的问题（2026-10-16 调整：原 3 个，用户要求给足候选自行挑选）。本 skill 只管**流量向**选题；确认题目后的起草流程在 **zhihu-answer-drafter** skill。带货向选题见 **zhihu-haowu-scout** skill。

公共流程（浏览器通道检查 / 选题画像 / 抓取问题列表 / 历史去重 / 关注问题池增速快照）见同目录 **`scout-common.md`**，本文件不再重复。

## 工作流程

### 5. 选题模型：曝光份额 × 机会 × 供给 × 问题类型

模型依据：一篇回答的期望收益 = 能被多少人看到 × 看到后愿意互动的概率 − 写作成本；四因子即对这三项的拆解（回测依据见 `analytics/选题模型复盘-2026-09-07.md`）：

- **D 曝光份额（每条回答能分到多少曝光）**：核心指标 = 浏览量 ÷ 回答数。10 万浏览 200 回答的题，每条只分到 500 曝光；1000 浏览 3 回答的题，每条分到 333。累计浏览量和关注者数只作辅助参考——看问题的人多不代表会看你的回答，落到后面给谁看？
- **O 机会（竞争格局）**：回答数少、头部回答赞数低 = 前排空缺。但低 D 题的前排空缺是陷阱（没人看的题排第 1 也没用），O 在低 D 时封顶。
- **M 供给（素材复用度）**：降低权重（1-3 分）。回测发现 M=5（素材直接复用）的题没有比 M=3 的题表现更好——内容复用降低写作成本，但不决定读者买不买账。
- **Q 问题类型（最强预测因子，2026-09-04 新增）**：知识类篇均阅读 425 / 赞同 3.3，推荐类仅 171 / 0.9——相差 2.5 倍 / 3.7 倍。问题类型比主题更能预测表现。

**总分 = D × O × M × Q（乘法，满分 300）**。用乘法：任一因子接近零，期望收益就是零。

#### 5.1 硬否决（任一命中即淘汰，不打分）

- 用户没有一手经验的边界领域（医疗/法律/金融投资等，遵守根 AGENTS.md）
- ~~超出用户本人知识储备、用户无法为内容站台的题~~（2026-08-23 曾因此整篇作废，但 2026-10-16 用户裁决：此条否决取消——无一手经验/知识边界的题也可以推，只要内容基于公开资料查证、不编造即可。此类题在选题单「注意」里标注知识门槛供用户定夺，不做硬否决；根 AGENTS.md 的医疗/法律/金融投资红线仍然有效）
- **死问题：关注者 <6，直接否决**（2026-09-04 调整：原 100→6。实测 100 门槛杀伤过大，当前邀请/推荐池 80 题中 0 题过 100 关注；历史数据中关注 6-50 的题也有跑出 500+ 阅读的case。关注 ≥6 是问题有最低可发现性的实证底线）
- **曝光份额过低：浏览 ÷ 回答 < 50，直接否决**（2026-09-04 新增。即使关注者 >100，如果浏览/回答 <50，说明每条回答分到的曝光极少，排前排也没意义。实证：性价比高的充电宝推荐 2800浏览÷36回答=78，篇均阅读 37）
- **回答数过多：>70 条回答，直接否决**（2026-10-16 调整：原 >50，用户权重提升后放宽。历史依据：30-40 回答的大题排 20-30 名仍分到 400-1000 阅读，大题是权威投资不是放弃。≤10 回答好冲前排，11-30 甜蜜区，31-50 流量可观但排不进前 10，51-70 沉底风险高但权重提升后可搏，>70 否决）
- **问题活性不足（2026-10-12 重构：不再以「最近一条新答的日期」单信号判定——单条新答可能是广告小号刷的假活性，且常青搜索题本就没有持续新答）**。活性分档（判定法见 5.2）：
  - **活跃**：近 30 天新答 ≥3 条 → 过；
  - **常青活**：近 30 天新答 <3 条，但 浏览÷回答 ≥200 且 关注者 ≥ 回答数×2（搜索流量题的典型形态：看的远多于答的）→ 过，D 打分封顶 3（5.3）；
  - **枯竭**：以上都不是 → 否决。**累计浏览量只代表历史，不代表当下日活**——浏览 >1 万但回答数 <10 且近 30 天无新答的题，是流量高峰已过的「遗迹」（复盘实证：10.8 万浏览的「快充协议」题仅 6 个回答，排第 4 阅读只有 8；若有流量早有几十人来答），不满足常青活条件的一律否决。
- 读完问题描述后发现题主诉求与标题不符、或实际主题与本仓库领域无关

#### 5.2 两阶段漏斗

- **阶段 A 粗筛（只看标题和来源，不打开问题页）**：凭领域匹配快速排除，保留 ≤8 个进入精评。近重复主题不排除，带上撞题标注进入精评（见 5.6）。
- **阶段 B 精评（逐个打开问题页）**：navigate → sleep 3 秒 → 先抓统计数据，再按 zhihu-answer-drafter 第 2 步的脚本抓问题描述（同一次访问完成两件事）。
- **阶段 B 前预检（2026-10-22 新增，可选）**：对候选题先跑官方 CLI `question answers --question-url <URL> --limit 20`，用返回的回答摘要快速识别「前排全是广告答/引流答」的供给空虚题（真机会）和「摘要内容与标题严重不符」的题，提前淘汰或标注，减少问题页打开次数。⚠ 该接口**没有赞数**，O 打分的 T 值仍必须以问题页 topUps 为准；只作活性与内容形态粗判。与问题推荐共用 `question_discovery` 额度（100 次/日）。

统计抓取脚本（已实测：问题页数据区文本为「关注者\n数字\n被浏览\n数字」，用 `body.innerText` + 正则，对 DOM 改版更鲁棒；topUps 为 2026-08-29 新增，按 DOM 顺序取默认排序前 5 条回答的赞数，回答卡片选择器如失效需实测校准）：

```js
(()=>{const t=document.body.innerText;const num=re=>{const m=t.match(re);if(!m)return 0;const v=parseFloat(m[1].replace(/,/g,""));return Math.round(v*(/万/.test(m[0])?1e4:1))};const ups=[...document.querySelectorAll(".ContentItem.AnswerItem, .List-item")].map(el=>{const m=(el.innerText||"").match(/([\d.,]+万?)\s*人赞同了该回答/);if(!m)return null;const v=parseFloat(m[1].replace(/,/g,""));return Math.round(v*(/万/.test(m[0])?1e4:1))}).filter(v=>v!==null);return JSON.stringify({follow:num(/关注者\s*([\d.,]+万?)/),view:num(/被浏览\s*([\d.,]+万?)/),answers:num(/([\d.,]+万?)\s*个回答/),topUps:ups.slice(0,5)})})()
```

抓不到数字时用 `snapshot` 人工读取「关注者 / 被浏览 / x 个回答」三个数；`topUps`（默认排序前 5 条回答的赞数）抓不到就人工读前 5 条的赞数，都不打 0 分。

阶段 B 另需记录**问题生命周期信号**（2026-10-12 重构）：①近 30 天新答**条数**（问题页切「按时间排序」，数首屏日期在近 30 天内的回答条数；不是只看最新一条的日期——单条新答可能是 8 个月静默后的偶然一条，也可能是广告小号刷的假活性）；②新答质量校验：最新 1-2 条新答的答主粉丝数和内容形态（全文只推一个商品/引流微信 = 广告答）。近 30 天仅 1-2 条新答且最新答为广告小号 → 按静默处理（5.1 枯竭判定）；前排全是广告答反而是机会（真实供给空虚），在选题单「注意」里注明。这两个值是 5.1 活性判定和 5.3 D 打分的依据，写入选题单数据快照和第 7 步历史表。问题创建时间（问题日志可见；⚠️ 实测坑：日志页正则抓日期时第一个日期是最近编辑日志、创建时间是最后一个，取 last 不取 first）照常记录。

#### 5.3 打分细则（2026-09-04 重构）

**D 曝光份额（1-5 分）**——量「每条回答能分到多少曝光」，不量问题总流量：

核心指标 = **浏览量 ÷ 回答数**。辅助信号：活性档（2026-10-12 起替代「近 7/30 天有新答」单信号，判定见 5.1/5.2）。

| 分 | 浏览÷回答 | 且 |
|----|-----------|-----|
| 5 | ≥5000 | 活跃 |
| 4 | ≥1000 | 活跃 |
| 3 | ≥200 | 活跃或常青（**常青封顶 3**——搜索流量题吃长尾但不吃推荐爆发） |
| 2 | ≥50 | —— |
| 1 | <50 | —— |

注意：硬否决已在 5.1 拦截了 浏览÷回答 <50 的题，所以 D=1 的题是刚过否决线的边缘题。关注者和累计浏览量只作辅助参考，不进主公式。若该问题在 `analytics/followed-pool.jsonl` 里有 ≥2 次快照且日浏览增量 >500，D 直接 ≥4（增速是「此刻有流量在进」的最强证据，2026-10-12 起接口预留，攒数据期内默认不触发）。

**O 机会（1-5 分）**——门槛赞数 T = 默认排序第 5 名回答的赞数（topUps 第 5 个值；回答不足 5 条时 T=0）：

| 分 | 条件 |
|----|------|
| 5 | T ≤ 5（第 5 名个位数赞，或不满 5 条回答） |
| 4 | T ≤ 50 |
| 3 | T ≤ 500 |
| 2 | T ≤ 2000 |
| 1 | T > 2000 |

修正项：

- **低 D 封顶**：D ≤ 2 时，O 封顶 3 分。低曝光题的前排空缺是陷阱——没人看的题排第 1 也没用（实证：3 个关注者的题排第 1，阅读 7）。
- **回答数修正**（2026-10-16 更新）：回答数直接影响冲前排难度——≤10 回答 O +1（封顶 5），11-30 回答不调整（甜蜜区），31-50 回答 O -1（大题流量可观但前排固化），51-70 回答 O -2（沉底风险高，靠内容质量搏）。硬否决已拦截 >70。
- **垄断但后排空虚不降档**：top1 赞数很高但 T 很低（如第 1 名 2000 赞、第 5 名 20 赞），按 T 值正常打分，不因头部赞数高降档。
- **能力对照（先验，2026-09-07 更新）**：账号 ~4000 粉但权重衰减，当前能力先验 **篇均 284 阅读 / 2.2 赞同**（依据：08-18 以来 46 篇全量数据，中位数 1 赞，P75 = 3 赞）。T ≤ 50 仍是主战场；T ≤ 500 需内容质量明显超出现有前排才选；T > 500 默认不选。

**M 供给（1-3 分）**——降权，不再隐含「成本低 = 质量高」的假设：

| 分 | 条件 |
|----|------|
| 3 | 领域内，有差异化角度可写（不是简单搬运已有内容） |
| 2 | 核心观点已有素材可复用，但需补新角度 |
| 1 | 擦边领域或完全无积累 |

先用 Grep 以问题关键词检索各话题归集目录（含 `_主稿/` 和问题文件夹），命中哪些文件决定档位，不凭印象。

**Q 问题类型（乘数 0.3 / 1.0 / 1.5 / 2.0）**——最强预测因子，按标题关键词判定：

| Q 值 | 问题类型 | 标题特征 | 实证篇均（46 篇） |
|------|----------|----------|---------|
| 2.0 | 知识/科普类 | 为什么、是不是、真的吗、什么原理、有什么区别 | 阅读 425 / 赞同 3.3 |
| 1.5 | 决策/对比类 | 该不该、有必要吗、够用吗、值得买吗、A vs B | 阅读 274 / 赞同 3.0 |
| 1.0 | 经验/方法类 | 如何、怎么做到、有什么技巧、经验分享 | 待积累，取中位 |
| 0.3 | 推荐/选购类 | 怎么选、哪个好、推荐、哪款、买什么 | 阅读 142 / 赞同 0.7（20 篇，6 篇 0 赞） |

判定规则：以标题主句型为准，不看描述。标题同时含多种句型时（如「怎么选，是不是越贵越好」），取信息量更高的那个（知识 > 决策 > 推荐）。

**主题维度观察（2026-09-07 新增，非正式因子）**：主题方向的影响大于问题类型。苹果生态类（Mac/iPad/iPhone 选购决策）13 篇篇均阅读 489 / 赞同 3.2，充电器配件类 33 篇仅 202 / 1.7——差 2.4 倍 / 1.9 倍。粉丝画像（25 岁以下 60.5%、涨粉主力 iPad/教育优惠）进一步放大苹果类优势。**选题角度优先锚定苹果生态 + 学生场景**；泛充电器/充电宝题除非能改造为苹果生态角度（如「MacBook 宿舍一个充电器搞定」），否则预期打折。

**排序规则**：总分 = D × O × M × Q，取前 7（2026-10-16 调整：原前 3）；并列时来源优先级（关注 > 邀请 > 推荐），再并列比近期活跃度（最近新答日期更近者优先）。

#### 5.4 校准回路（科学方法的闭环）

选题历史表记录打分时的「关注/浏览/回答数/T/最近新答」快照（见第 7 步）。回答发布后回采两个时点：**24 小时赞数**（检验冷启动测试曝光给不给量）和 **7 天赞数 + 当时排名**（稳态结果），在历史表追加「复盘」行。回采调用 **zhihu-answer-tracker** skill 完成（创作中心批量采五指标 + 问题页抓排名 + 回写复盘行）。

复盘数据维护两个量：

- **能力先验**（我方回答能拿到的赞数区间）：现行值见 5.3「能力对照」（2026-09-07：篇均 284 阅读 / 2.2 赞同，中位数 1，P75=3）。每攒约 10 条新复盘按实际分布更新，并同步修订 5.3；
- **分档阈值**：若实际排名系统性优于/差于 O 档预期（如 T ≤ 50 也持续打不进前 5），调整 5.3 的 T 分档。

历史复盘明细（2026-08-31 / 09-04 / 09-07 三轮全量回测的过程记录）已移至 `analytics/选题模型复盘-2026-09-07.md` 存档；结论均已固化进现行规则，改阈值前先读该存档了解来历。

#### 5.6 重复主题注明机制（2026-08-28 起）

主题撞题不再淘汰，但**入选时必须特别注明**，让用户知情决策：

- **完全重复**：与已发布/已有草稿主题相同 → 选题单里标注「⚠ 重复主题：与《xxx》撞题」，并写清新的切入角度是什么；想不出新角度才在「注意」里说明风险，由用户决定答不答。
- **部分重叠**：部分内容可复用但问题侧重不同 → 标注「⚠ 部分重叠：与《xxx》重叠在 xxx 部分」，写清本题侧重点是哪里、重叠内容怎么换说法（避免两篇回答文字雷同被平台判重复内容）。
- 注明格式固定在选题单的「注意」字段，前缀 `⚠ 重复主题` / `⚠ 部分重叠`，一眼可辨。
- 近重复题仍记入 `选题历史.md`（标注撞题对象），但不再写「不再推荐」——它的作用是供下轮选题时查撞题、写注明。

### 6. 输出选题单

**硬性要求：每个入选问题必须显式列出完整问题链接（裸 URL 单独成行，如 `- 链接：https://www.zhihu.com/question/xxxx`），不要只藏在 Markdown 锚文本里**——终端里锚文本不显示 URL，用户要的是可直接复制打开的链接。

```markdown
## 本次选题（共 N 个候选，粗筛 K 个，精评后选出 7 个）

### 1. [问题标题](问题URL)
- 链接：https://www.zhihu.com/question/xxxx（完整裸 URL，显式列出）
- 来源：关注 / 邀请 / 推荐
- 数据快照：关注 x / 浏览 x（累计）/ 回答数 x / 浏览÷回答 x / 创建于 x / 活性档：活跃（近30天新答x条）/ 常青 / 边缘
- 评分：D=? O=? M=? Q=? → 总分 ?（满分 300）
- 匹配理由：……（必须引用具体的已有文章文件名）
- 建议切入角度：……（指明可复用哪篇文章的哪些观点）
- 注意：……（如有事实核查点或风险；撞题题必须以 `⚠ 重复主题` / `⚠ 部分重叠` 前缀开头，见 5.6）
```

然后询问用户：要对哪些题目起草回答？确认后调用 **zhihu-answer-drafter** skill 起草。

### 7. 记录与收尾

落选/撞题记录（选题侧职责）：

- 用户明确排除的题目：不起草，把问题 ID 记入 `outlines/选题历史.md` 并在标题后标注「（已弃选，不再推荐）」。
- 浏览中遇到的**与已答主题近重复的题**也顺手记入历史（标注撞题对象，如「近重复：xxx」），供下轮选题写注明用——**不要再标「不再推荐」**，近重复题按 5.6 仍可入选。

把本次选出的问题追加到 `outlines/选题历史.md`（含打分时的数据快照，供 5.4 校准回路回采）：
