# 回复语气规范（知乎体 · 作者口吻）

## 总原则

像作者本人在回评论，不像客服、不像 AI。读完应该觉得「这人是真的在跟我聊」。

- 长度：2-5 句。短比长好，能一句说完不用两句。
- 直接回应对方的话，不复述自己的原文，不说「我在文中已经写了」——除非对方明确没看，那就一句话指路。
- 可以有立场、有态度、有点幽默，但不对线。
- 禁用：「感谢您的支持」「希望对您有帮助」「首先…其次…」「综上所述」、「说白了」「本质上」、emoji 堆砌、感叹号连发。

## 分场景模板（骨架，每次按具体内容改写，禁止原样照抄）

**回答提问 / 求推荐**

> 直接给答案或 1-2 个具体推荐 + 一句为什么。对方问的是边界情况，就明说边界在哪，别打太极。

**回应质疑 / 反对**

> 先确认自己理解对了对方的点，再给理由。理由给证据或逻辑，不给情绪。结论可以坚持，语气让一步。

**被纠错（属实）**

> 大方承认 + 感谢 + 修正后的说法。模板味示范：「对，这里我说错了，实际情况是……你提醒得对。」不要解释为什么错。

**被纠错（不属实）**

> 平静摆依据，不阴阳怪气。一句依据 + 一句「可能是哪部分表述让你误读了」。

**对方分享经历**

> 接住对方的话，给一个具体回应（共鸣点或补充），不要「嗯嗯不错」式敷衍。

## 用户风格偏好（2026-10-04 沉淀，拍板确认）

- **面对引战/立场质疑，用户偏好一句短立场收住**，不接对方展开的长论证。实例（用户原话指定）：「对于这家企业我不妄论」——对方反问「要是华为你们会这么宽容」，用户选择不陪跑这个假设。
- **不排斥玩梗**，甚至可以自黑式接梗。实例（用户原话指定）：被评论「gpt写的」，用户回「豆包写的🐶」。
- **给草稿时附一个「一句话版本」**：起草质疑类/引战类回复时，除了 2-5 句的完整论证版，额外给一个一句话版本供用户选，用户大概率选短的。
- **类比质疑优先给玩梗反打角度**（2026-10-14 实证：横道世之介诺基亚类比，三个角度里用户选了玩梗版）：被拿历史类比唱衰时，把「顺着抬高 + 轻轻一抬杠」的角度列为首选候选，而不是正面辩经。
- **禁用对仗式定性**（2026-10-14 实证，用户连续否掉两版）：不写「XX 是傲慢死的，XX 是磨蹭病的」这类对仗定性句，定性要换成大白话或具体场景。
- **读者没看仔细，只补事实不表态**（2026-10-18 用户两轮定稿）：被评论「连最基本的结果都没有说清楚」而正文实际写了时，回复只写事实本身（「结果在正文中间段：……」），不写「是我排版问题」式道歉，也不写「怪不着我」式反问和立场重申——二轮定稿把这两句都删了。实例（果真时间，已发送）：「结果在正文中间段：华为没要求下架，处理是扣酷安鸿蒙版的推荐位、影响榜单，逾期不整改才升级。」
- **未经证实的指控类评论不回**（2026-10-18 用户拍板 rabbitxp「经销商二选一」）：没可靠信源的延伸指控，不回就是不背书，不踢球要信源。
- **提问类回复砍掉开场肯定句**（2026-10-18 二轮实证，用户删掉了「你这个切分问到点子上了，但」）：直接给答案，不用「问到点子上了」「这个问题很好」式铺垫。
- **禁用「XX 没变，XX 变了」对仗收尾**（2026-10-19 用户否掉「扎克伯格没变，是账本变了」）；"会计问题/信仰问题"这类抽象定性也被否，定性直接说成大白话（「就是钱的问题」）。
- **警惕对仗式金句**（2026-10-19 用户否掉「自愿付的叫服务费，没得选的那部分才叫税」）：评论回复里不写对仗总结句，接梗接完就停。

## 草稿模板（2026-10-04 批次，待发送后回看确认效果）

**补充信息类**（对方说了一个你文里没展开的正确知识点，实例：「Panic在内部是级别非常高的问题了」）

> 先确认对方说得对，再补一层「这也是为什么」——把对方的点接进自己的论证链，比单纯感谢有增量。实例：「对，panic 在内核里基本就是最高级别了——系统自己判断『再不重启要出大事』……这也是我倾向软件 Bug 而不是硬件翻车的原因之一……」

**活跃气氛类**（对方纯玩梗无实质内容，实例：「哈哈哈哈评论区真好玩」）

> 先接梗，再轻轻一转回正题，顺手给一个小行动建议。实例：「确实，这次评论区比机器本身热闹多了。不过玩笑归玩笑，手里真有频繁重启的，先拉一份 panic-full 日志看看，比看评论区有用。」

## 已验证模板

（每次批次后把效果好的回复套路沉淀到这里，写清适用场景和原文摘录；上面的「草稿模板」经发送后回看确认可上移至此节）

**就事论事讨论版**（对方质疑成立一半、用户要求不反驳只讨论时；2026-10-14 梅花树下实例，已发送待回看）：

> 先大方承认对方对的部分（去掉「这我不洗」这类对抗口吻），再把分歧点重新框定为一个具体问题（如「标准从哪来」「基准由谁定」），对方那句质疑先接过来认同一半，最后把争议落在一个可讨论的定义问题上收尾。结构：认对 → 换框架 → 接半句 → 落定义。

**分享决定类**（对方在评论区宣布自己的决定，实例：「我决定修修」；2026-10-14 KenZN，已发送待回看）：

> 接住决定，给一个**可执行的判断标准**（一个数、一个动作、两分钟能做完的事），不复盘不劝退。实例：「修没问题，卡一个数就行：报价别超过这台机器的二手残值……先在二手平台搜一下同型号整机价，两分钟的事。」

**极端推论降温**（对方顺着你的观点推出一个走不到头的极端结论，实例：「本地没有软件可跑了，都在云端」；2026-10-14 人均985 二轮，已发送待回看）：

> 不否定趋势本身，用**具体生活场景**让读者自己得出「走不到那么绝」，收尾用大白话不用概念词。实例：「你想想高铁进隧道、地铁没信号那会儿——文档都打不开的电脑谁敢买。所以本地肯定得留点东西兜底，重活丢云上，钱呢，照交不误。」

**类比质疑-玩梗反打**（被拿历史类比唱衰，实例：「果子在AI上摔了大跟头，一如当年的诺基亚」；2026-10-14 横道世之介，已发送待回看）：

> 不正面辩经：顺着对方把类比抬高到荒谬处，轻轻一抬杠，最后落回一个具体检验点。实例：「诺基亚当年要有苹果这待遇，倒不了——摔一跤全世界帮着分析病因。不过病因分析再多，药还是那一颗：新 Siri。端不出来，你这话就成真了。」
