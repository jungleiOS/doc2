# fact-checker —— 文稿事实核查 Skill

对刚产出的文章（知乎回答、公众号长文、百家号转写稿）做「代码 review 式」事实核查：抽取可证伪声明 → 分级 → 逐项核查 → 出审校报告。**只做裁判，不做编辑**——不直接改正文，只出报告供作者人工仲裁。

## 触发场景

- 用户说「审校这篇」「核查事实」「fact check」「review 一下这篇稿子」
- 被 zhihu-answer-drafter 成稿后自动调用（在「去 AI 味」之前）
- 对已发布老回答做回填核查

## 铁律

1. **不改正文**。所有问题写入审校报告，由作者确认后另行修改。
2. **事实与推测分开写**。报告中每条判定必须附证据（来源 URL + 原文关键句 + 信源发布时间）或明确标注「无法证实」。
3. **禁止瞎猜**。查不到就是查不到，标「无法证实」，绝不能为了让报告好看而编一个来源。
4. **高危项 100% 核查，中危项抽样核查（至少 30%）并在报告注明**，低危项只列清单不核查。
5. 报告里同时记录**误报/漏报**：作者仲裁时对每条判定标注「采纳/误报」，累积成改进依据。

## 执行流程

### 第 1 步：声明抽取

通读全文，把所有可证伪的陈述逐条列出并编号。声明分四类：

| 类型 | 例子 | 示例编号 |
|---|---|---|
| 数据 | 「2025年Q3华为出货量同比增长30%」 | D1、D2… |
| 事实 | 「iPhone 17 全系支持80W快充」 | F1、F2… |
| 因果/对比 | 「因为3C新规，充电宝涨价是必然」 | C1、C2… |
| 引用 | 「据IDC报告，……」 | Q1、Q2… |

以观点形式出现但伪装成事实的（「所有人都知道xx不行」）也抽出来，归 C 类。

### 第 2 步：分级

每条标注风险等级：

- **高危**：具体数字（百分比、价格、参数）、时效性数据（销量/份额/政策）、医学/法律/投资建议、具体型号名。
- **中危**：行业判断、趋势断言、因果推理、未给信源的引用。
- **低危**：常识、观点表达、修辞性夸张。

### 第 3 步：逐项核查

按 `checklists/data.md`、`checklists/logic.md`、`checklists/quotes.md` 执行。核查方式优先级见 `references/source-grading.md`：一手信源 > 官方渠道 > 权威媒体 > 聚合站，禁止用另一个 AI 的回答当信源。

每项核查记录四要素：**来源 URL、信源发布时间、原文关键句、与稿中陈述的差异**。

同时执行三个专项：

1. **数字自洽性**：文章内部数字交叉验证（分项加总、前后一致、单位换算）。
2. **反向核查**：列出「作者没覆盖但读者会质疑的事实」——漏掉的竞品新款、没提的口径限定、忽略的反面证据。
3. **立场一致性**：用 Grep 检索同话题目录下已发布内容和 `问题对应表.md`，检查新稿与作者既有立场是否矛盾。

### 第 4 步：判定

每条给出五选一判定：

- ✅ 属实
- ⚠️ 部分属实（注明偏差，如口径/时间点/四舍五入问题）
- ❓ 无法证实（建议改标「据公开资料」或删除）
- ❌ 错误（必须修改）
- 🔴 高危错误（错误且涉医疗/法律/投资建议，一票否决，发布前必须改）

### 第 5 步：输出审校报告

写入被审文稿同目录，文件名 `审校报告-<原稿名>.md`，模板见 `references/report-template.md`。

报告结构：总评（一句话）→ 高危错误速览表 → 逐条明细（编号/原文位置/判定/证据/修改建议）→ 反向核查清单 → 立场冲突检查 → 误报记录表（留给作者填）→ 可入事实库条目。

### 第 6 步：事实库落盘

核查属实且有稳定来源的事实，追加到 `references/事实库.md`：`事实 | 来源 | 核查日期`。后续写作可直接引用，避免重复核查。

## 与其他 Skill 的关系

- 上游：khazix-writer / zhihu-viral-answer / zhihu-answer-drafter / zhihu-to-baijiahao 的产出稿。
- 下游：作者仲裁 → 执行修改 → 再去 AI 味 → GEO 审查（zhihu-geo-optimizer）。
- 不替代人工终审：涉及个人经历真实性、立场边界的判断必须问作者（见 AGENTS.md §6.2）。
