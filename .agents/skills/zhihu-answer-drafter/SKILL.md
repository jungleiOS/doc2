# 知乎回答起草助手（zhihu-answer-drafter）

把确认要答的知乎问题写成回答初稿。选题侧流程（怎么选题、打分）在 **zhihu-question-scout** skill；本 skill 只管「题定了之后怎么写」。带货向起草（好物选品与插卡）在 **zhihu-haowu-drafter** skill，不在本 skill 范围。

## 工作流程

浏览器通道检查、读问题完整描述（含逐点回应/指代纪律/不编造台词/修辞字面语法/术语门槛）、事实核查与迭代改稿流、配图工作流、去 AI 味、立场句标注兜底、数据校验、GEO、存档登记，全部与 **zhihu-haowu-drafter** 共用，见同目录 **[drafter-common.md](drafter-common.md)**（锚点：§1 浏览器通道检查 / §2 读问题完整描述 / §3 事实核查与迭代改稿流 / §4 配图工作流 / §5 去 AI 味 / §5.5 立场句标注兜底 / §5.7 校验数据准确性 / §6 GEO/SEO 审查 / §6.5 成稿打分 / §7 存档与登记），本文件不再重复。

### 1. 决策卡（2026-10-11 起，核心环节）

读完问题完整描述后、动笔成稿前，agent 先交付一张**决策卡**给作者仲裁。原则：agent 做信息收集和选项生成，作者只做选择题——逐项「认/不认 + 一句理由」，理由写多烂都算数，但不许只给「感觉不对」；不认的项 agent 必须改，且改动不得波及其他项。立场最终仲裁权永远在作者。

**交付方式（2026-10-18 起，硬规则）**：决策卡必须以**普通文字消息**贴在对话里交付，逐维度写清（立场候选含推荐及理由，其余项含结论与置信度），末尾请作者逐项仲裁。**禁止用结构化选择题组件（AskUserQuestion/选项按钮）**——选择框逼作者在预设选项里二选一，无法表达「都不要，我有第四种立场」这类跨维度组合意见，也砍掉了作者写理由的环节。作者用自由文字回复（可逐条说、可只否一条、可推翻推荐），agent 据此执行；作者未回复前不得动笔成稿。（带货起草侧的决策卡交付方式与此相同，见 zhihu-haowu-drafter。）

**触发条件**：观点分歧题/选购题必做全卡；纯经验求助题（无立场可分）自动缩水为「战场分析 + 流量类型」两项，禁止为走流程在无分歧的题上硬凑立场候选。

**六个维度**（每项注明分工：agent 产出 / 作者仲裁）：

1. **立场候选（2-3 个）**〔agent 产，作者裁〕：每个立场含——一句话核心观点（结论前置版）/ 支撑逻辑 2-3 条（哪些事实撑得住，须先行事实核查）/ 受众与风险（讨好谁、得罪谁、是否逆主流——逆主流流量高但要求论证更硬）/ 与作者已有文章口径一致性检查（今天说 A 明天说 A 的反面 = 消耗人设）。附 agent 推荐 + 推荐理由，标注「推荐仅供参考，仲裁权在作者」。agent 只列作者真能站得住的立场，列明知作者不信的选项是浪费仲裁时间。
2. **战场分析**〔agent 产，作者扫一眼〕：用 ego-browser 在问题页按「默认排序」抓前 5 条回答 + 点开高赞折叠补抓前 3 条，总样本 5-8 条；每条只提 5 字段：赞同数 / 发布时间 / 核心立场一句话 / 结构类型（故事流/清单流/数据流）/ 时效风险。时间预算 5 分钟，一个 evaluate 脚本批量提，不做逐条精读。
   **观点分析（抓完必须做，不是列完就完）**：把 5-8 条的核心立场摆在一起看格局，回答三个问题：
   - **共识带**：前排答案立场扎堆在哪？（比如全是「支持涨价论」）扎堆处 = 已占领地带，站进去就是给第一名做注释；
   - **空白带**：哪些合理立场没人站？（比如没人替「受害者视角」说话）空白带 = 差异化机会，候选立场优先从空白带出；
   - **共识带的最薄弱环节**：如果主流立场有一个共同回避的论据/事实（比如都绕开了某个实测数据），它就是攻击点——逆主流立场要打赢，打的必须是这个环节，不是笼统地唱反调。
   三种局面与策略：前排全是情绪/抖机灵 → 认真作答+数据扎实=降维打击；前排已有强答案且立场同质 → 差异化立场（优先空白带）或建议弃答（作者已授权弃答选项）；前排答案过时（参数换代）→ 「现在还能用吗」式更新打法。抓取失败时降级为「战场未知」并写明，立场候选照常给。
3. **流量类型**〔agent 产〕：搜索型（经验求助/选购：吃长尾，结论前置+GEO 那套）vs 推荐/热榜型（观点/热点：吃开头 100 字完读率和互动，开头必须有钩子）。决定开头写法与详略。标注：此维度由知乎分发机制决定，高置信。
4. **人设影响**〔agent 产，作者裁〕：作者人设锚点——「理工科视角、用实测数据拆营销话术」。标注这篇是巩固 / 消耗 / 立体化（人格立体化=偶尔跨界但判断方式一致，是涨粉项不是风险项）。逆主流立场短期阅读高但论证软被打脸时，消耗的是人设，亏的是长期复利。
5. **争议预埋**〔agent 产，作者裁，高阶选项〕：1 个站得住但有讨论空间的点（引评论，算法吃互动）+ 预判杠点及文内处理方案（让评论区吵在预设战场上）。仅观点题使用，且启用此维度时事实核查标准须加严。标注：**未在本账号验证，小规模试行，属假设非规则**。
6. **时效等级**〔agent 产，作者裁〕：抢发（热点 48h 内：走快车道——压缩迭代改稿轮次、配图底线降为 2-3 张真实图；**事实核查与立场仲裁不压缩**，这两环出错代价远大于晚发半天）vs 可打磨（走完整迭代流）。此维度由分发机制决定，高置信。

**证据分级**（写进卡里供作者参考）：维度 2、3、6 = 机制决定，高置信；维度 1、4 = 复盘数据支持；维度 5 = 未验证假设，小规模试。

决策卡通过仲裁后，把「结论摘要」（一句话：选的什么立场/流量类型/抢不抢发）记下来，存档时登记（见 drafter-common §7）。

### 2. 成稿执行（本 skill 特有项）

公共成稿规则（调用 zhihu-viral-answer、迭代改稿流、事实核查、子代理并行）见 drafter-common §3，此处只列本 skill 特有执行项：

- **成稿必须严格执行决策卡结论**：立场、开头钩子、争议点以仲裁结果为准；成稿中若发现决策卡判断有误（如读到描述细节后流量类型判错），**回到决策卡重新走仲裁**，不静默改。
- **素材优先复用归集目录里的主文和已有回答**，保持一致的口吻和「文尾引流」固定写法，但**篇章结构必须逐篇差异化**（2026-08-31 复盘：8 天 12 篇统一「先说结论 + 实测案例 + 引流」骨架，疑似被算法判批量生产遭降权）——开头钩子、展开顺序、详略分布每篇换一种组织方式，不允许多篇套同一模板。
- **段落长度纪律（2026-10-16 起）**：正文单段超过约 150 字必须换行分段——手机端和窄窗口电脑端长段阅读压力大，这是排版硬规则，成稿自检时逐段数字数。

## 禁忌

- 不替用户实际提交/发布任何回答，绝不点发布按钮。
- 禁止只看问题标题就起草；未读问题完整描述写出的稿子必须作废重写。
- 观点分歧题/选购题禁止跳过决策卡直接成稿；纯经验求助题允许缩水版（战场分析+流量类型），禁止为走流程硬凑立场候选。
- 起草不编造第一手体验；用户未提供的设备/经历不写进回答，涉及参数先核查再落笔。
- 配图红线、去 AI 味红线、事实核查红线见 drafter-common §4/§5/§3，带货起草的选品与插卡红线见 zhihu-haowu-drafter。
