# 知乎带货选题助手（zhihu-haowu-scout）

从用户的知乎**关注的问题 + 邀请回答 + 创作中心推荐问题 + 官方问题发现**中（来源优先级：**关注的问题 > 邀请 > 推荐 > 官方推荐**——前三者抓取与画像模式推荐见 `../zhihu-question-scout/scout-common.md` §3，带货场景主题模式推荐建议用选购词：`--query '充电宝推荐'`、`--query '充电器 选购'`、`--query '耳机 求推荐'`），基于「曝光份额 × 机会 × 供给 × 购买意图」四因子模型（见第 5 步），每次选出期望收益最高的**带货向**问题（数量同普通 skill，7 个）。本 skill 只管带货选题；确认题目后的起草流程在 **zhihu-haowu-drafter** skill。流量/涨粉向选题见 **zhihu-question-scout** skill。

公共流程（浏览器通道检查 / 选题画像 / 抓取问题列表 / 历史去重 / 关注问题池增速快照）见 `../zhihu-question-scout/scout-common.md`，本文件不再重复。

## 工作流程

### 5. 选题模型：曝光份额 × 机会 × 供给 × 购买意图

带货回答的期望收益 = 流量 × 前排机会 × 素材供给 × **读者下单概率**；前三个因子与普通 skill 同构，第四个因子用购买意图 P 替代问题类型 Q（带货不怕题「小」，怕的是读者不买东西）：

- **D 曝光份额**：同普通 skill 5.3 的 D 分档。
- **O 机会**：同普通 skill 5.3 的 O 分档（门槛赞数 T、回答数修正、低 D 封顶、能力对照全部沿用；注意回答数修正区间随本 skill 硬否决上限调整，见 5.1）。
- **M 供给**：同普通 skill 5.3 的 M 分档。
- **P 购买意图（乘数，替代普通 skill 的 Q）**：按标题购买意图分档：

| P 值 | 购买意图 | 标题特征 |
|------|----------|----------|
| 2.0 | 明码求购 | 求推荐、预算 xx、哪款、买什么、有必要买吗 |
| 1.5 | 对比决策 | A vs B、选哪个、XX 好还是 YY 好 |
| 1.0 | 场景触发 | 大学生/宿舍/出差 + 选购词弱组合 |
| 0.3 | 泛讨论 | 为什么、怎么看、有什么影响 |

⚠️ **如实注明**：P 档位为逻辑推断，**无回测实证**（普通 skill 的 Q 档有 46 篇回测支撑，P 档没有）。后续按 5.4 校准回路积累数据后再固化。

**总分 = D × O × M × P（乘法，满分 300）**。用乘法：任一因子接近零，期望收益就是零。

#### 5.1 带货专用硬否决（任一命中即淘汰，不打分）

替代普通 skill 5.1 中的对应条目，其余条目（用户没有一手经验的边界领域、题主诉求与标题不符等）与普通 skill 一致：

- **死问题：关注者 <6 且 浏览÷回答 <200，才否决**（普通版：仅关注 <6 即否决。带货吃搜索长尾，低关注高浏览的搜索题是常态）
- **曝光份额过低：浏览 ÷ 回答 < 30，直接否决**（普通版为 <50。带货题单条曝光价值更高，下限放宽）
- **回答数过多：>150 条回答，直接否决**（普通版为 >70。购物意图题转化不看全站排名，只看搜索前排，大题也可做）
- **问题活性不足**：枯竭仍否决；**常青活不封顶 D**（普通版常青封顶 3）——**常青搜索题是带货主战场**（读者带搜索框里的购买意图而来，转化链路最短）。活跃/常青活/枯竭判定法与普通 skill 5.2 相同。
- 读完问题描述后发现题主诉求与标题不符、或实际主题与本仓库领域无关

#### 5.2 两阶段漏斗

- **阶段 A 粗筛（只看标题和来源，不打开问题页）**：凭领域匹配与购买意图快速排除（泛讨论类、无选购词的题直接不进精评），保留 ≤8 个进入精评。
- **阶段 B 精评（逐个打开问题页）**：navigate → sleep 3 秒 → 先抓统计数据，再按 zhihu-answer-drafter 第 2 步的脚本抓问题描述（同一次访问完成两件事）。

统计抓取脚本（同普通 skill，已实测；topUps 按 DOM 顺序取默认排序前 5 条回答的赞数）：

```js
(()=>{const t=document.body.innerText;const num=re=>{const m=t.match(re);if(!m)return 0;const v=parseFloat(m[1].replace(/,/g,""));return Math.round(v*(/万/.test(m[0])?1e4:1))};const ups=[...document.querySelectorAll(".ContentItem.AnswerItem, .List-item")].map(el=>{const m=(el.innerText||"").match(/([\d.,]+万?)\s*人赞同了该回答/);if(!m)return null;const v=parseFloat(m[1].replace(/,/g,""));return Math.round(v*(/万/.test(m[0])?1e4:1))}).filter(v=>v!==null);return JSON.stringify({follow:num(/关注者\s*([\d.,]+万?)/),view:num(/被浏览\s*([\d.,]+万?)/),answers:num(/([\d.,]+万?)\s*个回答/),topUps:ups.slice(0,5)})})()
```

抓不到数字时用 `snapshot` 人工读取「关注者 / 被浏览 / x 个回答」三个数；`topUps` 抓不到就人工读前 5 条的赞数，都不打 0 分。

阶段 B 另需记录**问题生命周期信号**：同普通 skill 5.2（近 30 天新答条数、新答质量校验、问题创建时间），这两个值是 5.1 活性判定和 D 打分的依据，写入选题单数据快照和第 7 步历史表。

**阶段 B 顺带产出迷你决策卡原料（2026-10-22 起）**：决策卡已前移到选题阶段——阶段 B 打开问题页抓统计/好物卡的同一次访问中，顺手完成以下原料采集，随选题单一并交付（成品格式见 5.5.1）：

- **前排回答样本提取（战场结论）**：回答数 ≥15 的题，按 drafter-common 战场分析的三问（共识带/空白带/最薄弱环节）给一段结论；回答数 <15 的题前排即全部答案，降级为一段战场结论，不逐条抓 5 字段。
- **流量类型判断**：搜索型 vs 推荐流型，给高置信的单一结论。
- **时效等级判断**：抢发 vs 可打磨，给高置信的单一结论。

- **阶段 B 前预检（2026-10-22 新增，可选）**：同普通 skill 5.2——先用官方 CLI `question answers --question-url <URL> --limit 20` 的回答摘要识别「前排全是广告答/引流答」的供给空虚题与题文不符的题，提前淘汰或标注，减少问题页打开次数。**但注意**：带货场景该预检**不能替代**阶段 B 的前排好物卡检查（摘要里不显示好物卡片），好物卡竞争修正必须仍在问题页完成。与问题推荐共用 `question_discovery` 额度（100 次/日）。

**已有好物卡竞争修正（阶段 B 强制项）**：抓统计时顺带看前排（默认排序前 5 条回答）是否有好物推荐卡片 / 京东链接：

- 前排已有 ≥2 张好物卡 → 类目转化被验证，**P 升一档**（如 1.5→2.0；已是 2.0 不升），O 仍按 T 正常打分；
- 前排 0 张好物卡且题为明码求购 → 选题单「注意」标注「类目未验证」，用户定夺。

#### 5.3 打分细则

**D / O / M 分档**：沿用普通 skill 5.3 的表格与修正项（低 D 封顶、垄断但后排空虚不降档、能力对照先验），仅两处差异：

- 常青活题 D **不封顶 3**（对应分档行写「活跃或常青（带货不封顶）」）；
- 回答数修正区间随硬否决上限调整：≤10 回答 O +1（封顶 5），11-30 不调整，31-70 O -1，71-150 O -2，>150 硬否决。

**P 购买意图**：按 5 节 P 档表判定标题主句型；标题同时含多种句型时取购买意图更高的那个；叠加阶段 B 的好物卡竞争修正。

**排序规则**：总分 = D × O × M × P，取前 7；并列时来源优先级（关注 > 邀请 > 推荐 > 官方推荐），再并列优先「推荐插」好物结论的题，再并列比近期活跃度。

#### 5.4 校准回路

与普通 skill 分线回测：历史表记录打分时的数据快照，回答发布后回采 **24 小时**与 **7 天**两个时点，调用 **zhihu-answer-tracker** skill 完成。带货 KPI **优先采好物点击/出单数据**（若创作中心可见），赞数只作代理指标。

分线维护两个量：

- **能力先验**：带货回答的赞数/点击代理区间，与普通 skill 分开统计（带货回答赞数天然偏低，不可混入普通先验）；
- **P 档回测**：P 档目前为逻辑推断无实证，每攒约 10 条带货复盘按实际出单/点击表现校准 P 分档与好物卡竞争修正。

#### 5.5 好物评估与插卡时机（阶段 B 顺带完成）

阶段 B 打开问题页时已拿到标题、描述和数据快照，逐题给出三档结论：**推荐插（商品方向）/ 可插不优先 / 不插**（附一句话理由和商品方向）。选品与商品级核查（是否有真实实测商品、好物库可挂、卡的商品与正文同款）调用 **zhihu-haowu-drafter** skill（商品级选品与核查已并入该 skill）。

- 好物结论**不进 D×O×M×P 总分**——好物是变现维度，不是流量维度，混进总分会扰乱选题排序。
- 总分并列时，优先「推荐插」的题。
- 结论写进选题单（第 6 步），供用户决定选品方向和插卡时机（起草侧不再代执行插卡）。
- **插卡时机默认延迟（2026-08-31 起）**：带商品卡的回答遭商业降权，叠加 0 互动冷启动失败直接沉底。默认策略为**首发不带卡、纯干货抢前排，发布 48h 后若排名进前 5 或赞数达到能力先验区间，再编辑插入商品卡**。仅当问题本身是强购买意图（题主明码求购，如「预算 200 求推荐充电宝」）且好物评估为「推荐插」时，才允许首发直接插卡。

#### 5.5.1 迷你决策卡（2026-10-22 起，随选题单交付）

选购/带货题决策卡收敛为 4 项，由本 skill 在阶段 B 顺带产出（原料见 5.2），随选题单逐题交付：

1. **战场结论**：一段结论，含共识带/空白带/最薄弱环节三问结论（回答数 <15 的题降级为一段结论，不逐条抓）；
2. **立场 = 选品候选**：1-2 个选品方向 + agent 推荐及理由（立场候选与选品合并，「推荐哪类」即立场）；
3. **插卡时机**：48h 后延迟插（默认）/ 首发直插（仅强购买意图题）；
4. **风险标注**：含选品红线核查结论（哪些商品是作者真实实测过的，随商品级核查给出）；争议预埋维度在选购/带货题正式删除，不再保留。

**仲裁机制**：迷你决策卡随选题单一并交付，作者在确认选题时**一次性仲裁**（逐项「认/不认 + 一句理由」）；未回复项视为认可，但**未获作者确认前不得动笔起草**。作者确认选题 = 仲裁通过，随后调用 **zhihu-haowu-drafter** 直接成稿，起草阶段不再重复产出决策卡。

#### 5.6 重复主题注明机制

同普通 skill 5.6（⚠ 重复主题 / ⚠ 部分重叠，注明固定在「注意」字段，近重复题仍记入历史表不标「不再推荐」）。

### 6. 输出选题单

**硬性要求：每个入选问题必须显式列出完整问题链接（裸 URL 单独成行，如 `- 链接：https://www.zhihu.com/question/xxxx`），不要只藏在 Markdown 锚文本里**。

```markdown
## 本次选题（共 N 个候选，粗筛 K 个，精评后选出 7 个）

### 1. [问题标题](问题URL)
- 链接：https://www.zhihu.com/question/xxxx（完整裸 URL，显式列出）
- 来源：关注 / 邀请 / 推荐 / 官方推荐
- 数据快照：关注 x / 浏览 x（累计）/ 回答数 x / 浏览÷回答 x / 创建于 x / 活性档：活跃（近30天新答x条）/ 常青 / 边缘 / 前排好物卡 x 张
- 评分：D=? O=? M=? P=? → 总分 ?（满分 300）
- 好物评估：推荐插（商品方向）/ 可插不优先 / 不插（一句话理由，按 zhihu-haowu-drafter 结论）；插卡时机：48h 后延迟插（默认）/ 首发直插（仅强购买意图题）
- 迷你决策卡（见 5.5.1，随选题单交付、确认选题时一次性仲裁）：
  - 战场结论：……（共识带/空白带/最薄弱环节三问结论；回答数<15 的题为一段降级结论）
  - 立场 = 选品候选：候选 1 / 候选 2（agent 推荐：x，理由：……）
  - 插卡时机：48h 后延迟插（默认）/ 首发直插（仅强购买意图题）
  - 风险标注：……（含选品红线核查结论：哪些商品为作者真实实测）
- 匹配理由：……（必须引用具体的已有文章文件名）
- 建议切入角度：……（指明可复用哪篇文章的哪些观点）
- 注意：……（如有事实核查点或风险；「类目未验证」、撞题题必须以 `⚠ 重复主题` / `⚠ 部分重叠` 前缀开头，见 5.6）
```

然后询问用户：要对哪些题目起草回答？**确认选题 = 仲裁迷你决策卡（逐项「认/不认 + 一句理由」，未回复项视为认可，但确认前不得动笔）**；确认后调用 **zhihu-haowu-drafter** skill 直接成稿（起草阶段消费仲裁结论，不再重复产出决策卡）。

### 7. 记录与收尾

落选/撞题记录、历史表追加：同普通 skill 第 7 步，差异：

- 历史表「类型」列记「**带货**」（2026-10-21 起新增）；
- 复盘行按 5.4 分线回测，带货 KPI 优先记好物点击/出单（若创作中心可见；官方 CLI `me content-stats` 的 Metrics 暂无好物点击/出单字段，2026-10-22 实测仅流量与互动指标，该 KPI 仍以创作中心为准）；
- 回写完成后同样关闭浏览器会话：`completeTaskSpace('zhihu-scout', { keep: false })`，必须放在独立最后一个 heredoc 里执行，且只在前序输出确认任务真正完成后才调用。

## 禁忌

- 不替用户实际提交/发布任何回答或商品卡，只做选题；起草规则见 zhihu-haowu-drafter。
- 禁止推荐 关注<6 且 浏览÷回答<200 的问题；禁止推荐 浏览÷回答 <30 的问题；禁止推荐回答数 >150 的问题；禁止把累计浏览量当作当下流量依据。
- 不编造问题数据；抓取失败就如实说明，不假装看到了列表。
- 打分必须有抓到的数据支撑（D/O 按快照对档，M 按已有文件对档，P 按标题句型对档），禁止凭感觉拍分；数据抓不到就如实标注并降级处理。
- 选题理由必须引用具体的已有文章文件名，禁止空泛的「和你的领域匹配」。
- 好物结论不进总分；默认延迟插卡，仅强购买意图题允许首发直插。
